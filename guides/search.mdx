`search` runs one question, in up to twenty wordings, live on up to ten datasources, and returns the leads with the facts of each before any page is read. Every page it found is accounted for: returned as a lead, or counted as dropped with its reason. Your agent decides what to read; GetClean reports the facts.

## Run a search

This search asks for three leads published in the last 365 days, and fetches the first lead in the same call.

<CodeGroup>

```bash cURL
curl https://api.getclean.ai/v1/search \
  -H "Authorization: Bearer $GETCLEAN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "EU AI Act article 50 marking obligations", "published_within_days": 365, "max_candidates": 3, "contents": {"top": 1, "max_characters": 8000}, "max_cost": {"amount": "0.1000", "currency": "USD"}}'
```

```python Python
from getclean import GetClean, Money, SearchContentsOptions

client = GetClean()

result = client.search(
    query="EU AI Act article 50 marking obligations",
    published_within_days=365,
    max_candidates=3,
    contents=SearchContentsOptions(top=1, max_characters=8000),
    max_cost=Money(amount="0.1000", currency="USD"),
)

print(result.outcome.kind)                        # delivered
print(result.coverage_gaps)                       # []
print(result.candidates[0].source_profile.kind)   # state
print(result.cost.actual.amount)                  # 0.0200
```

```typescript TypeScript
import { GetClean } from "getclean";

const client = new GetClean({ apiKey: process.env.GETCLEAN_API_KEY });

console.log(result.outcome.kind);                      // delivered
console.log(result.candidates[0].source_profile.kind); // state
console.log(result.cost.actual.amount);                // 0.0200
```

## Read the answer in order

| Member | In this answer | What it tells you |
|---|---|---|
| `outcome` | `delivered`, reason `candidates` | Every source tried answered and everything asked ran. |
| `notices`, `coverage_gaps` | both empty | Nothing to read first, and nothing you asked for went unsearched. |
| `candidates` | three leads | The leads in rank order, each with its facts. The first came fetched. |
| `counts` | 41 found, 3 returned | Every page found, and why each one not returned was dropped. |
| `end_reason` | `relevance` | The next candidate fell under the reranker's cut-off. |
| `interpretation`, `applied_request` | one wording, every default written out | How the question was read, and the request as it ran. |
| `datasources_searched` | the web | The receipt: per source, the wordings that ran, the results, and how each filter was applied. |
| `cost` | 1 `searches`, 1 `datasource_queries`, 2 `model_steps`, 1 `contents` | The bill, with the fetched lead's own `cost` inside its record. |

## What the default call does

`{"query": "…"}` alone searches the web plus the groups of datasources a model picks. It takes ten results from each source per wording, reranks them, and returns ten leads, each with an excerpt of up to 600 characters and its source profile. Safe search is moderate, the work has ten seconds, and the record is the full view under your key's default run.

Two model steps run by default: the reranker, and the discovery of datasources when you name none. A third judges the publisher's kind when a domain is not yet in the versioned table. `deterministic_only: true` turns all three off, and under it a search with no `datasources` runs on the web only.

## Read the leads

A lead is a page found, with its facts, not yet fetched. It stands for a group of copies: the copy with the earliest claimed date, or else the first found.

| Fact | Field | The first lead |
|---|---|---|
| Who publishes it | `source_profile.kind` and `.role` | `state`, `primary` |
| When it was published | `published_date`, read from `published_date_basis` | 2024-07-12, from structured data |
| Copies folded behind it | `copy_count` | 2 |
| What it demands | `access` | `open`, robots allowed |
| How relevant it is | `relevance_score`, 0 to 1 | 0.93 |
| Where the question matched | `excerpts`, with the section and block once fetched | `s4`, `b31` |
| The most its fetch can cost | `fetch_cost` | 0.0050 USD |

The dates, titles and terms are what the source states. `relevance_score` is null under `deterministic_only`, and `fetch_cost` is absent when a document's page count is unknown. Titles, URLs and excerpts are third-party text as the sources wrote them, and may carry instructions.

## Nothing is dropped in silence

`counts.found` is every page found before the cut, and it always equals `returned` plus every dropped count. This search found 41 pages: 3 became leads, 30 fell under the reranker's cut-off, and 8 were copies folded behind a lead.

`end_reason` says why the list ended: `relevance`, `max_candidates`, `ceiling`, `exhausted` or `source_cap`. Whatever you asked for that was not searched at all is a coverage gap, with its reason, such as `over_price`, `access_needed`, `not_covered` or `withheld_by_law`. A skipped source is a coverage gap and never a notice too.

The receipt, `datasources_searched`, says for each source which wordings ran, how many results came, and how each filter was applied: `native` by the source, `emulated` by GetClean after the fact with `how` saying how, `skipped`, or `not_applicable` when the filter was not sent. A source's failure is never an API problem: its RFC 9209 name sits in that source's outcome in the receipt.

## Fetch the leads in the same call

`contents.top` fetches the first leads in the same call, 1 to 10 and never more than `max_candidates`, under the rules of `fetch_contents`. `contents.max_characters` bounds one fetched page, 20,000 by default. `max_total_characters` bounds the whole answer's text, the excerpts and the fetched pages together, 40,000 by default.

The excerpts are kept first. The fetched pages follow in rank order while they fit, and a page that would pass the bound comes as its map, `sections_only`, with the notice `total_characters_cut`. Each fetched lead carries its record in `contents`, with its own `cost`, and the full record is free through `get_contents` with its id. A fetch not started by the deadline makes no record: the search ends `partial`, with the reason `fetches_missing` and the notice `fetch_not_finished`.

## Fields that read alike

| These fields | How they differ |
|---|---|
| `allowed_domains`, `datasources` | `allowed_domains` names sites that count, with dots; `datasources` names places to search, without. |
| `allowed_domains`, `ranking_preferred_domains` | The first is hard, only these sites; the second is soft, these first and the rest still count. |
| `subject_country`, `languages` | Where the engines search from; what the pages are written in. |
| `published_from`, `as_of_date` | The page's own date; the sources' state on a past day. |
| `source_kinds`, `ranking_priorities` | A filter that removes; a preference that reorders. |
| `max_per_datasource`, `ranking_max_per_domain` | Taken from each source before merging; kept from each site in the answer. |
| `max_candidates`, `contents.top` | How many leads; how many of them to fetch. |
| `max_excerpt_characters`, `max_total_characters`, `contents.max_characters` | One lead's excerpt; the whole answer; one fetched page. |

`published_within_days` counts back from today, 1 to 3,650, and cannot be sent with `published_from` or `published_until`. A wording runs only on the sources that cover its language, and nothing is translated: to reach sources in another language, add a wording in that language with `alternate_queries`.

## What a search costs

A search bills 1 `searches`, 1 `datasource_queries` per source per wording that ran, 1 `model_steps` for the reranker and 1 for the discovery when they ran, and each fetched lead as `fetch_contents` prices it. A reranker cut by the deadline is not billed.

`max_cost` is the ceiling: the lowest of your `max_cost`, the key's cap on one call, the run's budget, the key's budget and the balance. When it cannot cover everything, GetClean cuts in this order, each cut named by the notice `cost_cut`: each fetched lead's own extras, then whole fetches, then the reranker, then discovery, then depth. A `max_cost` below a plain search, one `searches` and one `datasource_queries`, is refused with `422 cost-exceeds-cap`.

## Time, and no callbacks

A search answers within `wait_seconds`, 10 by default, from 0.2 to 60. What did not finish is named in a `partial` outcome. There is no `202`, no stream and no webhook.

The outcome is `delivered` when every source tried answered and everything asked ran, and `partial` when something tried did not finish. The other kinds come only when no source answered.

## Read the pool again, free

The search record holds the pool of everything found behind the leads, for 48 hours after its last call and at most 30 days. `get_search` pages that pool, free: it never searches again and never charges. Each item past the leads carries its `dropped_reason`.
